# Starting from a fresh clone

A clone of this repository is the source, not the lab. Four things are deliberately not in it,
and nothing will work until they exist locally. This page says what they are and how to get each
one back.

If you skip this and go straight to the deployment guide, the first failure is
`New-LabSeeds.ps1` complaining it cannot find a public key, which is confusing rather than
informative.

## What a clone does not contain

| Missing | Why | How to get it |
| --- | --- | --- |
| `04-implementation/host/.lab-secrets/` | SSH key and console password. Never committed, in this repository or any other. | `New-LabSecrets.ps1`, then the two seed builders |
| `.cache/` | The manager package is 508 MB. Fetched and hash-checked rather than stored. | `tests/fetch-engine-package.sh` |
| `04-implementation/evidence/` raw output | Live runs record account names, addresses and task contents. | Regenerated by running the scenarios |
| Operating system images | Licensed installation media. | Ubuntu Server 24.04 and Windows 11 ISOs, from the vendors |

## Also needed on the host

- Windows with Hyper-V enabled, and an elevated PowerShell session.
- The Windows OpenSSH client, for `ssh` and `ssh-keygen`. Windows 11 ships it.
- Around 220 GB free. `New-Lab.ps1` checks and refuses below that.
- WSL with Ubuntu, only if you want to run the offline rule suite.

## Rebuilding the missing pieces

From `04-implementation/host/`, in an elevated PowerShell:

```
.\New-LabSecrets.ps1
.\New-LabSeeds.ps1
.\New-WindowsSeed.ps1 -WindowsIso <path to the Windows 11 ISO>
```

The first creates the SSH keypair, a 20 character console password and its SHA-512 crypt hash.
The other two read those and build the three unattended installation images. Running them out of
order fails immediately rather than producing a broken image.

`New-LabSecrets.ps1` will not overwrite an existing set without `-Force`, because replacing the
keypair locks you out of any VM already built against the old one.

For the offline rule suite, from a shell that can reach the internet:

```
wsl -d Ubuntu --exec bash 04-implementation/tests/fetch-engine-package.sh
```

That downloads the Wazuh manager package and checks it against the SHA-256 published in the
signed apt index. A mismatch is deleted rather than kept, since a rule suite running against an
unverified engine proves nothing.

## Then

Follow [the deployment guide](../04-implementation/deployment-guide.md) from step 1.

Once the lab is up, `Lab.cmd` at the root of the repository opens the dashboard, which is where
you start and stop it from day to day.

## If you are rebuilding on the same machine

The lab occupies a fixed address range, `172.29.70.0/24`, and `New-Lab.ps1` refuses to run if
that range is already routed or if a NAT already exists. Remove the old lab first:

```
Get-VM WAZUH-MANAGER, WAZUH-WIN, WAZUH-LINUX | Stop-VM -TurnOff -Force
Get-VM WAZUH-MANAGER, WAZUH-WIN, WAZUH-LINUX | Remove-VM -Force
Remove-NetNat -Name Wazuh-Lab -Confirm:$false
Remove-VMSwitch -Name Wazuh-Lab -Force
```

That leaves the virtual disks on disk. Delete the storage directory separately once you are sure
you want to.
